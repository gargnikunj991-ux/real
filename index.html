LibroSphere (High-Concurrency Asset Engine)

Engineering Problem: High-concurrency checkouts of limited, single-copy inventory created severe race conditions, duplicate allocations, and inventory underflow (TOCTOU anomalies).

Architecture & Implementation: Engineered a high-concurrency asset lending and reservation backend in Java 21 and Spring Boot 3. Enforced JPA/Hibernate pessimistic row locks (@Lock(PESSIMISTIC_WRITE) / SELECT ... FOR UPDATE) within atomic @Transactional boundaries. Architected a state-driven FIFO waitlist queue (WAITING → NOTIFIED_READY) with auto-expiring 48-hour pickup windows, an idempotent midnight cron worker (@Scheduled) for tiered overdue fine calculations, and composite B-Tree indexing.

Impact & Results: Verified thread safety and ACID resilience through an automated 64-test JUnit 5 suite running 50 concurrent checkout worker threads (CountDownLatch), achieving 0 oversells and slashing database query latency from 120ms to under 15ms.

Java 21 Spring Boot 3 PostgreSQL 16 Spring Data JPA Pessimistic Locking ACID Transactions B-Tree Indexes JUnit 5 (64 Tests)
